# ANDROID BACKEND WITH TELEMETRY & MAP & HEATMAP 

Система для мониторинга параметров сотовой связи и геолокации в реальном времени. Приложение принимает данные от смартфона по протоколу ZMQ, визуализирует их на карте, строит графики сигналов и сохраняет историю в PostgreSQL.

## Основные возможности
* **Real-time сервер:** Прием и парсинг JSON-пакетов через ZeroMQ.
* **Отрисовка мапы:** Многопоточная подгрузка и кэширование тайлов OpenStreetMap на диске.
* **Аналитика:** Визуализация метрик RSRP, RSSI и SINR в реальном времени через ImPlot.
* **Хранение данных:** Логирование в JSON-файлы и трансляция в PostgreSQL.
* **Оптимизация:** Разделение логики на независимые потоки.

## Архитектура

Приложение спроектировано по модульному принципу, где каждый компонент отвечает за свой уровень логики:

| Модуль | Описание |
| :--- | :--- |
| **`main.cpp`** | Инициализация графического контекста (OpenGL 3.3 Core Profile), запуск потоков и главный цикл отрисовки. |
| **`telemetry.cpp / .h`** | Сетевой стек (ZMQ), логика парсинга и хранение истории сигналов в структуре `PciHistory`. |
| **`gui_app.cpp / .h`** | Высокоуровневая отрисовка интерфейса, окон телеметрии и интеграция ImPlot. |
| **`map_engine.cpp / .h`** | Движок карт: управление очередью загрузки тайлов через `libcurl` и работа с текстурами. |
| **`database.cpp / .h`** | Слой абстракции для работы с БД PostgreSQL через библиотеку `libpq`. |
| **`heatmap.cpp / .h`** | Движок для отрисовки тепловых точек на карте по имеющимся логам. |

## Тепловая карта (Heatmap)

Модуль тепловой карты реализован в `heatmap.cpp / .h` и визуализирует пространственное распределение метрик сотовой связи на карте.

### Метод интерполяции
Используется метод обратных взвешенных расстояний (IDW). Для каждого пикселя тайла значение вычисляется как взвешенная сумма измерений в радиусе R:
Радиус интерполяции настраивается в диапазоне 10–40 метров, степень p регулирует "жёсткость" градиента.

### Поддерживаемые метрики
| Метрика | Диапазон | Описание |
| :--- | :--- | :--- |
| **RSRP** | -110 … -80 dBm | Мощность опорного сигнала |
| **RSRQ** | -20 … -10 dB | Качество опорного сигнала |
| **RSSI** | -110 … -40 dBm | Общая мощность принятого сигнала |
| **Altitude** | 0 … 3000 м | Высота над уровнем моря |

### Фильтрация
В интерфейсе доступна фильтрация по **EARFCN** (частотный канал) и **PCI** (идентификатор соты), что позволяет визуализировать зону покрытия конкретной базовой станции.

### Архитектура модуля
Вычисление разделено на два этапа:

* **Worker Thread** — генерирует PNG-изображение тайла (256×256) методом IDW и сохраняет на диск.
* **Main Thread** — при следующем кадре обнаруживает готовый файл и загружает его в OpenGL-текстуру.

### Кэширование
* Сгенерированные тайлы сохраняются по пути `build/zoom/x/y_heat_M_E_P.png`, где M — метрика, E — EARFCN-фильтр, P — PCI-фильтр.
* При смене метрики, радиуса или фильтра кэш сбрасывается автоматически (`heat_invalidate_cache()`).
* Дедупликация очереди через `std::set` исключает повторную генерацию одного тайла.

### Цветовая шкала
Значения отображаются градиентом: синий (минимум) → зелёный → жёлтый → красный (максимум). Легенда с подписями отображается поверх карты в правом верхнем углу окна.


### Модель потоков:
* **Main Thread**: Обработка событий SDL2 и рендеринг GUI.
* **Server Thread**: Фоновый прием данных по сети, обновление `LocationData` и запись в БД.
* **Tile Loader Thread**: Асинхронная загрузка изображений карт, исключающая фризы интерфейса при плохом интернет-соединении.
* **Heatmap Worker Thread**: Асинхронная генерация тайлов тепловой карты методом IDW, исключающая фризы интерфейса.

## Данные и логи
* **Кэш карт**: Тайлы сохраняются по пути `build/zoom/x/y.png`.
* **JSON Лог**: Все входящие пакеты записываются в файл `location_log.json` в корневой папке.
* **PostgreSQL**: Данные о каждой соте пишутся в таблицу для последующего анализа.
